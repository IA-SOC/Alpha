# Adding a test case

**Goal:** widen coverage and catch regressions.
**Files:** depends on the kind of case (table below).

## 1. Decide what kind of case it is

| Kind | Folder | For what | Test file |
| --- | --- | --- | --- |
| **Synthetic agent case** | `data/synthetic/` | Test the procedure: formats, times, IoC, hostile text, ambiguity. May be tuned to the rules. | `tests/test_agent_graph.py` |
| **Contract case** | `examples/` or `examples/test_cases/` | Test intake, correlation and IoC through the API | `tests/test_pipeline.py`, `tests/test_correlation_engine.py`, `tests/test_ioc_integration.py` |
| **Holdout** | `data/holdout/` | Measure detection. **Not** used to write rules or prompts. | None |

Ideally someone who did not touch the rules writes it, using real Elastic or Wazuh rule names.

## 2. Write the case

Formats in [[04 Case format]]. Recommendations:

- Use documentation IPs: `192.0.2.0/24`, `198.51.100.0/24` and `203.0.113.0/24`. Never real IPs.
- Include at least one hard element: a plausible benign explanation, a time without a zone, a missing field or a text that tries to give instructions.
- For contract cases, also include **correlation edge cases**: two alerts sharing only an IP (should be `uncertain`), alerts just outside the 300 s window, an alert with no comparable entities.
- Write down separately which techniques and which pair classifications you expect. That is the **reference** of the case.

## 3. Run it

```powershell
python agent/graph.py data/synthetic/my_case.json 2>$null       # agent case
```

For a contract case, start the server and submit it (see [[03 Daily use]]), or use `demo/run_pipeline.py` as a template.

## 4. Add it to the tests

**Agent case**, in `tests/test_agent_graph.py`, add it to three dictionaries:

```python
CASES = {
    # ...
    "my_case": ROOT / "data" / "synthetic" / "my_case.json",
}
EXPECTED_TECHNIQUES = {
    # ...
    "my_case": {"T1110"},       # what the agent MUST detect today
}
EXPECTED_FORMAT = {
    # ...
    "my_case": "wazuh",
}
```

Per-case tests are generated from `CASES`.

**Contract case:** follow the pattern of `test_two_related_alerts_across_sources` (pure correlation, no server) or `test_full_api_pipeline_reaches_real_langgraph_and_mcp` (full API flow with the test client). Assert the pair classifications and rules, not just that the call succeeds.

> [!note] Holdout cases do not go into the tests
> Tests lock in current behavior. If a holdout case enters `EXPECTED_TECHNIQUES`, it stops being a holdout.

## 5. Regenerate outputs

```powershell
python agent/run_synthetic.py      # all of data/synthetic/
python demo/verify_local.py        # if you changed the demo case
```

Holdout cases have to be run and saved separately:

```python
import asyncio, json
from pathlib import Path
from agent.graph import investigate

p = Path("data/holdout/kerberoast_rdp_rclone_ecs.json")
state = asyncio.run(investigate(json.loads(p.read_text(encoding="utf-8")), thread_id="holdout"))
out = Path("data/reportes_sinteticos/holdout_kerberoast")
out.with_suffix(".json").write_text(json.dumps(state["report"], indent=2, ensure_ascii=False), encoding="utf-8")
out.with_suffix(".md").write_text(state["report_markdown"], encoding="utf-8")
```
