# Adding a MITRE rule

**Goal:** make the agent recognize a new technique.
**Files:** `core/logic.py` and, if the tactic is new, `agent/investigation.py`.

## 1. Add the rule

In `core/logic.py`, add an item to `RULES`:

```python
RULES = [
    # ... existing rules ...
    {
        "match_any": ["kerberoast", "rc4 encryption", "tgs request"],
        "technique_id": "T1558.003",
        "technique_name": "Kerberoasting",
        "tactic": "Credential Access",
    },
]
```

- `match_any`: **lowercase** text fragments. One of them appearing inside the rule name or a tag is enough.
- `technique_id`: format `T1234` or `T1234.567`. The validator rejects anything else.
- `tactic`: the English name, exactly as in ATT&CK.

> [!example] Tested in the previous version
> With this rule, the holdout case detects `T1558.003` on alert `ho-002` ("Kerberos Service Ticket Requests with RC4 Encryption Burst"). `core/logic.py` has the same rules in both versions, so the result should carry over. Run it to confirm.

### Choosing the words

- **Too generic** words cause false positives: `"login"` would match almost any authentication alert.
- **Too specific** words match nothing: `"kerberoasting_detected"` only works if the rule has exactly that name.
- Use the real Elastic and Wazuh rule names from the client.
- Elastic tags use spaces (`Tactic: Lateral Movement`). To match them, add the fragment with a space: `"lateral movement"`.

## 2. If the tactic is new

If the tactic is not one of the current five (Initial Access, Credential Access, Lateral Movement, Exfiltration, Impact), add it in these places. Otherwise the agent still works, but with defaults: stage `progression`, no actions, priority `medium` and no alternatives.

**`core/logic.py`**

```python
TACTIC_ORDER = ["Initial Access", "Execution", "Credential Access", "Lateral Movement",
                "Persistence", "Exfiltration", "Impact"]

TACTIC_TO_STAGE = {
    # ...
    "Execution": "initial_access",
}

ACTIONS_BY_TACTIC = {
    # ...
    "Execution": [
        "Revisar el árbol de procesos en el EDR del host afectado",
        "Bloquear la ejecución de macros desde documentos de origen externo",
    ],
}
```

**`agent/investigation.py`**

```python
ALTERNATIVES = {
    # ...
    "Execution": ["Script administrativo legítimo lanzado desde una plantilla de Office."],
}
UNKNOWNS = {
    # ...
    "Execution": ["No se sabe qué ejecutó el proceso hijo ni si hubo conexión de red posterior."],
}
PRIORITY_BY_TACTIC = {
    # ...
    "Execution": "high",
}
```

> [!note] Keep report text in Spanish, or translate all of it
> The existing actions, alternatives and unknowns are in Spanish. Mixing languages in one report reads badly. If the client wants English reports, translate these dictionaries and `agent/render.py` together.

## 3. Check

```powershell
python agent/graph.py data/holdout/kerberoast_rdp_rclone_ecs.json 2>$null
python -m pytest -q
```

If `test_tecnicas_y_formato_esperados` fails, the new rule detects something in a synthetic case. Check that it is correct and, if it is, update `EXPECTED_TECHNIQUES` in `tests/test_agent_graph.py`.

> [!info] Correlation is not affected
> MITRE rules run after correlation and never influence it. A new rule cannot make two alerts `related`.

> [!warning] The holdout case
> If you wrote the rule while looking at the holdout case, that case no longer measures anything new. Create another holdout case before measuring. See [[12.6 Measuring precision]].
